# 전화 응대 매니저웹 배포 체크리스트

2026-11-17 재점검

Spring Boot(Java), React, WebSocket으로 만드는 전화 응대 매니저웹을 사내망 서버 한 대에 배포하는 기준입니다. 1번은 결과에 따라 설계가 바뀌므로 개발을 시작하기 전에 확인합니다. 클라우드에 올린다면 1번과 4번 항목이 달라집니다.

관련 문서: [개발 계획](dev-plan.md), [환경 설정](environment-setup.md)

## 1. 개발 전에 먼저 확인할 것

메일 릴레이와 외부 API 접근은 나중에 막히면 구조를 다시 짜야 하므로 가장 먼저 확인합니다.

- [ ] 서버 위치와 접속 주소 확정: 고정 IP 또는 내부 도메인, 방화벽 포트 개방
- [ ] 메일 발송 경로 확인: 사내 메일 서버가 SMTP 릴레이를 허용하는지, 발신 계정을 받을 수 있는지
- [ ] 서버에서 외부 LLM API 호출이 되는지 확인: 막혀 있으면 외부망 PC에서 JSON을 만들어 가져오기(import)하는 방식으로 설계
- [ ] 업무분장표(직원 이름, 업무)를 외부 AI에 보내도 되는지 보안 규정 확인
- [ ] 로그인 방식 결정: 자체 계정인지 사내 계정 연동인지

## 2. 빌드와 설정

- [ ] 배포 형태: React 빌드 결과를 Spring Boot에 넣어 jar 하나로 배포(개발 계획에서 확정)
- [ ] JDK 25(LTS)와 Spring Boot 4.1.x로 버전 고정, Gradle wrapper 포함
- [ ] dev/prod 프로파일 분리, DB 비밀번호와 SMTP 계정, API 키는 환경변수로 분리
- [ ] DB 스키마는 Flyway로 관리하고 운영에서는 `ddl-auto=validate`
- [ ] 서버 시간대 Asia/Seoul 설정: 자리비움 종료 시각과 자동 복귀에 직접 영향
- [ ] React 화면 주소에서 새로고침해도 화면이 뜨도록 서버가 `index.html`을 돌려주게 설정

## 3. 웹소켓

- [ ] Nginx를 거친다면 Upgrade 헤더와 유휴 타임아웃 설정
- [ ] HTTPS를 쓰면 `wss://`로 연결되는지 확인
- [ ] 허용 origin을 운영 주소로 제한
- [ ] 클라이언트 자동 재연결과, 재연결 시 전체 상태 다시 불러오기
- [ ] 서버 재시작 후 열려 있던 화면이 스스로 복구되는지 테스트

## 4. 보안과 개인정보

- [ ] 권한 분리: 관리자(업무분장, 배치도 수정)와 일반 직원(본인 자리 상태만 변경)
- [ ] 로그인이 있으므로 내부망이라도 HTTPS 적용
- [ ] CSRF 보호를 켠 채로 React가 토큰을 보내도록 설정, 세션 쿠키에 Secure와 SameSite 적용
- [ ] 전화 메모의 발신자 이름과 번호 보관 기간을 정하고 자동 삭제
- [ ] 알림 메일 본문에 발신자 정보를 어디까지 넣을지 결정

## 5. 운영

- [ ] 서버 재부팅 시 자동 시작(systemd 또는 Windows 서비스)
- [ ] DB 하루 1회 백업과 복원 테스트 1회
- [ ] 로그 파일 로테이션, 메일 발송 실패 기록과 재시도
- [ ] Actuator 헬스체크 주소로 서버 상태 확인
- [ ] 이전 버전 jar를 보관해 롤백 가능하게
- [ ] 인사이동 때 누가 데이터를 수정할지 담당자와 절차 지정

## 6. 오픈 직전 점검

- [ ] AI가 구조화한 업무와 담당자 데이터를 사람이 전수 검수
- [ ] 화면의 파티션 배치와 내선번호가 실제와 일치
- [ ] 모든 파티션의 메일 주소로 테스트 메일 발송
- [ ] 브라우저 두 개에서 상태 변경이 실시간으로 반영
- [ ] 자리비움 종료 시각에 자동 복귀, 주담당자 연가 시 부담당자 표시
- [ ] 전화 메모 등록부터 파티션 표시, 메일 발송, 회신 완료 체크까지 한 번에 통과
- [ ] 검색 실패 로그가 쌓이는지 확인
